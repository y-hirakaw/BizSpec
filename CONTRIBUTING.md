# Contributing to BizSpec

Thanks for your interest in contributing. This document covers the dev setup, project layout,
and the workflow for sending pull requests.

## Getting started

Requires Python 3.9+ (the project is constrained to Python 3.9 syntax). Using
[uv](https://github.com/astral-sh/uv) is recommended.

```sh
git clone https://github.com/y-hirakaw/BizSpec.git
cd BizSpec
uv pip install -e ".[dev]"

# Verify the install
uv run --with pytest pytest tests/ -v
uv run bizspec --version
uv run bizspec validate
uv run bizspec viz
```

The CLI smoke test (`validate` + `viz`) runs in CI on Python 3.9 and 3.12.

## Project layout

| Path | Role |
|---|---|
| `src/bizspec/cli.py` | argparse entry point, dispatches to subcommand modules |
| `src/bizspec/core/` | shared layer: `loader.py` (YAML I/O), `errors.py` (`VError`), `model.py` (TypedDicts), `prompt.py` (`confirm`) |
| `src/bizspec/viz/` | `bizspec viz` implementation: `layout.py` (DAG layout), `builder.py` (HTML assembly), `cmd.py` (entry), `templates/*.html` |
| `src/bizspec/{init,new,list,rename,renumber,search,validate}_cmd.py` | one CLI subcommand per file |
| `src/bizspec/skills/` | **source of truth** for Claude Code skills (`bizspec-refine`, `bizspec-refactor`); `bizspec init` copies these into `.claude/skills/` and overwrites without warning |
| `bizspec/` | sample BizSpec processes (used by tests and the bundled `bizspec viz` demo) |
| `tests/` | pytest suite — mirror new source files with a `test_<module>.py` |
| `docs/` | `yaml-spec.md` (schema reference), `cli.md` (CLI reference) |

When editing a Claude Code skill, **always edit `src/bizspec/skills/`**. The `.claude/skills/`
copy is regenerated by `bizspec init` and any local edits there will be lost.

## Development workflow

1. Fork the repository and create a topic branch:
   - `feat/<short-summary>` for new features
   - `fix/<short-summary>` for bug fixes
   - `docs/<short-summary>` for documentation
   - `refactor/<short-summary>` for code-only refactoring
2. Make your change and add or update tests under `tests/`.
3. Run the full check locally before opening a PR:
   ```sh
   uv run --with pytest pytest tests/ -v
   uv run bizspec validate
   ```
4. Open a pull request against `main`. Fill out the PR template and link any related issue.

### Constraints to remember

- **Python 3.9 syntax only.** Avoid `match` statements, `tomllib`, `typing.Self`, etc.
- **Sample YAML files must pass `bizspec validate`.** This is enforced by CI smoke test.
- **Don't edit `.claude/skills/` directly.** Edit `src/bizspec/skills/` instead.
- **Don't add runtime dependencies lightly.** The current runtime dependency is `PyYAML` only.

## Commit and PR conventions

- Use a short imperative summary (50 chars or so) on the commit subject line.
  Example: `Add --format json to bizspec list`
- If the change needs context, add a body explaining the *why* (not the *what* — the diff
  shows the what).
- The PR description should mention:
  - What changed and why
  - Linked issue (if any)
  - Whether tests were added or updated
  - Any breaking change

## Reporting issues and asking questions

- **Bug reports** → use the *Bug report* issue template
- **Feature requests / schema proposals** → use the *Feature request* issue template
- **Open-ended design discussion** → use [GitHub Discussions](https://github.com/y-hirakaw/BizSpec/discussions) (once enabled). Until then, open a `Feature request` issue and label it `discussion`.
