## 5. 差別化メッセージ（README 冒頭 3 bullets 案）

- **Executable, not decorative** — Mermaid や draw.io は描画ツール。BizSpec は executor / IPO / link を YAML で定義し、AI agent / script / human が実際に走らせる前提で設計する。
- **Git-native & AI-refactorable** — YAML は diff・PR レビュー・grep が効く。Claude Code Skills（`/bizspec-refine` `/bizspec-refactor`）から AI が業務を直接リファクタできる。
- **Cost-aware visualization** — `effort × frequency` のヒートマップで工程ごとの月間コストが可視化される。

## 7. CONTRIBUTING.md の章立て案

1. **Getting started** — clone → `uv pip install -e ".[dev]"` → `uv run pytest tests/ -v` → `uv run bizspec validate`
2. **Project layout** — `src/bizspec/`（CLI）/ `src/bizspec/skills/`（**正本**）/ `.claude/skills/`（生成物）/ `bizspec/`（サンプル仕様）
3. **Development workflow** — fork → topic branch（`feat/`, `fix/`, `docs/`）→ PR。テスト追加と `bizspec validate` パスが必須。Python 3.9 構文に限定
4. **Commit & PR conventions** — コミット 1 行サマリ。PR には関連 Issue・変更点・テスト追加内容・Breaking change の有無を記載
5. **Reporting issues / asking questions** — Bug/Feature は Issue Template、設計議論は GitHub Discussions（または `question` Template）

## 8. `.github/ISSUE_TEMPLATE/bug_report.yml` 最小例

```yaml
name: Bug report
description: Report a defect in BizSpec CLI or skills
labels: ["bug", "triage"]
body:
  - type: input
    id: version
    attributes:
      label: BizSpec version
      description: "Output of `bizspec --version`"
    validations: { required: true }
  - type: input
    id: python
    attributes:
      label: Python version
      placeholder: "3.11.7"
    validations: { required: true }
  - type: textarea
    id: repro
    attributes:
      label: Steps to reproduce
      description: Minimal YAML or command sequence
      render: shell
    validations: { required: true }
  - type: textarea
    id: expected
    attributes: { label: Expected behavior }
    validations: { required: true }
  - type: textarea
    id: actual
    attributes: { label: Actual behavior / error output }
    validations: { required: true }
```

## 9. good first issue 候補 3 件（Phase C7 用）

1. **シェル補完の追加** — `bizspec --install-completion bash|zsh|fish`。`shtab` 依存追加 + フラグ + テスト 1 本。スコープが `cli.py` に閉じる
2. **`bizspec viz` の manifest JSON 出力** — `_viz/manifest.json`（unit 一覧 + link 配列）を追記。viz モジュールへの純関数追加で済む。テストはゴールデン JSON 比較
3. **新スキル SKILL.md テンプレ + `bizspec new-skill <name>` コマンド** — `src/bizspec/skills/_template/SKILL.md` を 1 つ作り、CLI でコピー。既存 `bizspec new` の構造を流用できる

選定基準：既存テストパターンを真似られる / Python 3.9 構文制限に抵触しない / 外部 API 不要。
